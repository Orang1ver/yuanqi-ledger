# 数值待核清单（P8）

> 这是「食物库的数字准不准」的**待办台账**，不是结论。
> 起因：有人问「15 个饺子怎么算出 1860mg 钠的」——算术没错（15 × 20g = 300g，
> 300g × 620mg/100g = 1860mg），但**那两个数都没有可复核的来路**。
>
> 复现方式：见文末「怎么重新扫一遍」。

---

## 一句话现状

| 项 | 数量 |
|---|---|
| 食物库总条数 | **223** |
| **没有可复核出处**（`source` 是模糊口径） | **184** |
| 其中「通用成分值 / 按标准菜谱估算 / 按配方估算 / 餐馆做法估算」这类 | 176（43 种写法） |
| 命中了份量规则、但规则里**一句话都没说明口径**（生重/熟重/可食部） | **95** |

**这两件事都直接导致屏幕上出现"看起来精确、实际不可靠"的数字** ——
而这正是项目最想避免的（`README` 里写的「估不出来就不给数字」）。

## A. 优先核：高频 + 数值明显可疑

按「用户会不会记」× 「值可不可疑」排的。

| 食物 | 现在的值 | 来路 | 疑点 |
|---|---|---|---|
| **饺子** | 240 kcal / **Na 620** | 通用成分值（煮） | 300g 折合盐约 **4.7g**（接近一天上限）。速冻水饺标签常见 400~700mg/100g，620 属偏咸档但**无出处** |
| **馄饨** | 160 kcal / **Na 700** | 通用成分值（煮） | 比饺子钠还高，可馄饨个头更小 —— 两者至少有一个不对 |
| **红烧肉** | 460 kcal / Na 800 | 按标准菜谱估算 | 各家做法能差一倍（肥瘦、糖色、收汁） |
| **宫保鸡丁** | 210 kcal / Na 700 | 按标准菜谱估算 | 同上 |
| **蛋炒饭** | 180 kcal / Na 650 | 餐馆做法估算 | 一盘饭用多少油、几勺酱油，差别很大 |
| **方便面** | 472 kcal / Na 1144 | 通用成分值（含调料包） | 含整包调料；很多人只放半包 |
| **薯片** | 548 kcal / Na 500 | 通用成分值 | 品牌/口味差异极大 |
| **奶茶（全糖/半糖/无糖）** | 86 / 65 / 45 kcal，Na 均 40 | 按配方参数化估算 | 三家店能差一倍；钠是不是该有明显差异也要看 |
| **馒头** | 223 kcal / Na 165 | 通用成分值 | 无出处 |
| **肉包** | 227 kcal / Na 600 | 通用成分值 | 同上 |
| **油条** | 388 kcal / Na 585 | 通用成分值（油炸） | 同上 |
| **挂面** | 346 kcal / **Na 170** | 通用成分值（干重） | ⚠️ 见下面 B 的「真 bug」—— 它和份量表的口径**对不上** |

> 说明：`米饭` 的钠 2.5mg/100g 这类**不用核** —— 米本身几乎不含钠，量级是对的。
> 这一列挑的是"数值量级本身就可疑、或驱动结论"的条目。

## B. 份量口径没写清（95 条）

### ⚠️ 先说一个**真 bug**：挂面

| | 值 | 口径 |
|---|---|---|
| 库里「挂面」 | 346 kcal / 100g | **干重** |
| 份量表 `碗[面条]` | 一碗 250g | **没写生熟** |

「挂面」的别名含「面条」（`干面条`），所以「一碗挂面」会命中 `碗[面条] = 250g`。
**实测（`npm run probe`）**：

```
✓ 「一碗挂面」 → 挂面  (库 id: noodles-dry)
    折算：1 × 「一碗」250g = 250g（常见 150~350g）
    本条：865.0 kcal · 蛋白 26.3g · 脂肪 2.3g · 碳水 185.3g · 钠 425mg

✓ 「一碗面」 → 面条  (库 id: noodles-cooked)
    本条：275.0 kcal   ← 这条是对的
```

**高估 3 倍**，而且它拿的是「干重」的数去乘「一碗」—— 碗里装的从来不是干面。

修法（择一）：
- 给「挂面」单独一条份量规则，**按干面给**：`碗[挂面] = 干面 80g`
  （80g 干面 × 346/100 = **277 kcal**，正好对上一碗煮熟的面）；
  并把干面类从 `碗[面条]` 的 `match` 里排除（先命中先赢，位置比内容要紧）；
- 或给这些干面条目单独一条份量规则，并写明「一碗指煮熟后」。

### 顺带撞见的另一个缺口：「下了一碗挂面」会丢份量

```
✓ 「下了一碗挂面」 → 挂面
    折算：没写份量，按分类兜底 200g = 200g（估算）  ⚠ 估算
```

`LEAD_NOISE` 里有「吃了 / 喝了 / 点了 / 买了」，**没有「下了」「煮了」** ——
于是整句当成食物名去模糊检索，配到了挂面，但**份量和单位一起丢了**，退化成分类兜底的估算值。
与 0.6.1 修的「昨晚」是同一类（地雷 19 的同类：看起来对、数字错）。

修法：`LEAD_NOISE` 补 `下了 / 煮了 / 下了碗 / 煮了碗`。
⚠️ 补之前先想一遍地雷 19：**这些词里不能带量词**（「下了碗」把「碗」剥掉就重犯旧错）。

### 其余口径未写的（按量词归类）

| 量词 | 条数（约） | 典型条目 | 风险 |
|---|---|---|---|
| 份 / 盘 / 碗 | 40+ | 白粥、小米粥、面条、米线、玉米、红薯、紫薯、土豆、米粉（干）、红薯粥 | 粥/面/蒸薯类的"一碗/一份"**生熟差异明显** |
| 个 | 20+ | （多为水果，风险较低） | 可食部是否含皮/核 |
| 包 / 袋 / 盒 / 瓶 | 20+ | 零食饮品类 | 一般已带 note，风险较低 |
| 把 / 串 / 块 | 10+ | 花生（炒）、瓜子（炒） | 低 |

**真正要紧的是第一行**：`碗 / 份 / 盘` 配「煮/蒸/干」类食物。
`碗[米饭]=180g` 已经写了「指熟重」，是个好例子 —— 其余照它补即可。

## C. 其余无出处条目（184 − 上表）

按分类汇总，不逐条列：

| 分类 | 条数 |
|---|---|
| （全部） | 184 |

这些的处理方式不是"逐条找权威值"，而是**分两步**：

1. **能被官方平台覆盖的** → 按 `data/foodSources.json` 的格式补引用（0.6.0/0.6.1 已经这么做了 39 条）；
2. **官方平台没有的**（如饺子、馄饨、成品菜） → 走 P6.1 第二批的**按配方估算**：
   列原料 → 查表 → 折算熟重（生熟比）→ 出油率 → 加权和，
   `source` 写成「按配方估算（参照《中国食物成分表》）」，并**在份量表里写明生熟口径**。

## 怎么重新扫一遍

本次扫描用的是一次性脚本（已删），逻辑是：

1. `data/foods.zh.json` 里 `source` **不含**「中国食物成分表」的 → 无出处；
2. 对每条食物，用与运行时相同的子串规则（`match.some(m => names.some(n => n.includes(m)))`）
   找出它命中的份量规则；这些规则的所有档位里**一个 `note` 都没有**的 → 口径未写；
3. 重点嫌疑：`source` 带「煮/蒸/干/炒/油炸/烤/煎」字样，或名字属米面类。

> 这份扫描**没有进仓库**（它是一次性的）。要做成常驻闸门的话，
> 应该并入 `scripts/check-nutrition.mjs` 的「份量表联动」那一节 —— 见下。

## 建议的下一步

**P8 剩下的这部分不适合一次做完**（184 条），建议拆：

1. **先修 `挂面` 那个口径 bug**（它会让一碗面算成 865 kcal，是本次最严重的一条）；
2. **给 `碗 / 份 / 盘` 里生熟有差异的条目补 `note`**（约 40 条，纯文案，不改数值）；
3. **把「口径未写」变成闸门**：`check-nutrition.mjs` 里加一条 ——
   命中 `碗/份/盘` 且 source 带做法字样的条目，其份量规则必须有 `note`，
   否则报错。**新增检查照例要自证会失败**；
4. 数值本身的校准（饺子/馄饨/红烧肉…）放到 P6.1 第二批，用配方估算重做。
