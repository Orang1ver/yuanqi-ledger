## 二、各阶段详情

### P0 · 数据层骨架（✅ 已完成）

`lib/storage/` 18 个 `recipe.*` 键名与 JSON 结构逐字保留；`check:data` / `smoke` 两道闸门落地。
**成果**：老数据零迁移直接可用。

### P1 · 营养数据层（✅ 已完成）

`data/foods.zh.json`（184 条）+ `data/foodPortions.json`（82 规则）+ `lib/nutrition/` 纯函数核心 + 单测。
**核心红线确立**：数字只有一条来路 `nutritionOf(食物,克数)`；「没有数据」≠「0」；快照语义。

### P2 · 饮食记录入口（✅ 主体完成，条码转出）

自然语言一句话记录 + 确认卡 + 口语解析（三种份量写法）。**条码扫描本属 P2，但一直没做，**
因它需要联网查库、违背「纯前端、数据只存本地」的前提 —— 已转入 **P6** 统一处理数据源问题。

### P3 · 分析呈现（✅ 已完成）

热量环、三大营养素供能比、逐项对比、饮食质量分（七维度）、一条该改的建议。

### P4 · 推荐与菜单库打通（✅ 主体完成，AI 转出）

`lib/nutrition/menu.ts`（菜名拆配料估热量区间）+ `lib/nutrition/recommend.ts`（`suggestForGaps` 按缺口打分）
+ 首页「今天还该吃点啥」。**「AI 推荐外卖」本属 P4，但需要模型接线，转入 P5。**

### P5 · 智能推荐 + 记录体验打磨（🔶 进行中）

**5.1 AI 推荐外卖（已定方案，最高优先，完成升 0.4.0）**
- 单任务接线：点一下 → 一次调用 → 2~3 个候选。不是 agent。
- 红线：LLM 只消歧与措辞，**绝不吐营养数字**；数字由本地 `estimateDish()`/`nutritionOf()` 算。
- 完整移交方案：`docs/HANDOFF-AI-RECOMMEND.md`。

**5.2 「一顿饭一键记」（用户点名痛点）**
- 0.3.0 只做了「餐次选择」这一半；还差「选常见搭配（盖饭/一菜一汤/两菜一汤）一次落多条记录」。

**5.3 份量档位点选**
- 现在改克数是手输数字，改成点「小包/一包/大包」更快（`portionOptions()` 已算好，只差 UI）。

**5.4 口语解析边界补强**
- 补「两三个」「半杯」「一打」等数量词与更多量词；守 `AGENTS.md` 第 15 条（静默算错是重罪）。

### P6 · 数据源扩容（⬜ 未开工，用户核心诉求「食品库内容不够多」）

**6.1 食物库扩容（重点）**
- 现状：184 条（staple 28 / meat 28 / veg 18 / protein 17 / fruit 20 / snack 21 / drink 19 / soup 13 / seasoning 16 / alcohol 4）。
- 缺口：**成品菜条目几乎没有**（黄焖鸡、麻辣烫、宫保鸡丁…），导致菜单识别率仅约四成。
- 扩容路径（两条并行）：
  - **高频成品菜**：补一批常见成品菜条目，**每条必须过数值校准**（对照权威成分表），不能拍脑袋填。
  - **份量表联动**：新增条目同时补对应 `foodPortions.json` 规则，且 `match` 能真命中食物名/别名。
- **红线**：宁可少加，不可错加。数值错的条目比没有更糟（`check:nutrition` 只证自洽、证不了数值全对）。

**6.2 条码扫描**
- 从 P2 转入。涉及联网查库 + 数据源许可，要**先定数据源与许可**（不能引入来源不明的数据），
  再决定是「浏览器直连某个开放库」还是「离线内置条码表」。
- 若没有干净的数据源，**可以不做**，别为凑功能引入许可风险。

### P7 · 覆盖维度深化（⬜ 未开工）

- **睡眠 / 心情分析**：这两项已在「今天」页记录（`dailyCheckins`），但目前只有周报达标率。
  补「睡眠趋势」「心情与饮食/运动的关联」。
- **体重趋势更丰富**：`lib/weight.ts` 已有记录与图表，补「目标体重进度」「周均体重」。

### P8 · 数据可信度加固（⬜ 未开工）

- **数值人工校核**：`check:nutrition` 只证「算术自洽」，证不了「数值全对」。需一套参照集
  （权威食物成分表）抽检 184 条的关键项（尤其钠、热量）。这是 1.0.0 及格线的一部分。
- **份量表与食物库联动校验**：新增条目自动查「有没有对应份量规则、match 能否命中」。

### P9 · 体验与收尾 → 1.0.0（⬜ 未开工）

- **导出/同步体验**：`lib/storage/backup.ts` 已能做备份，补「久未备份时提醒」「导入预览更友好」。
- **文案表统一**：界面文案散在各组件，抽一个文案表便于改口径。
- **更多冒烟定向检查**：每新增一类「只能靠交互/时间看出来的 bug」，补一条能自证失败的检查。
- **性能复查**：食物库扩容（P6）后，重新核对各页面 chunk 体积（食物库只进饮食页/菜单库/首页）。

## 四、红线与发布纪律（每次都要遵守）

- 版本号唯一来源 `package.json`，三处同步：`package.json` / `CHANGELOG.md` / `lib/changelog.ts`。
- 成块新功能 → MINOR；修 bug / 文案 / 样式 → PATCH；只改文档不升。
- 用户还看不到的成块工作，先记 `CHANGELOG.md` 的 `## [未发布]`，不动版本号。
- **1.0.0 起**：每次改动先开分支，用户确认后才 `--no-ff` merge 回 `main`。0.x 直接推 `main`。
- 红线摘要（完整见 `AGENTS.md` 第 3、4 节）：`recipe.*` 键名逐字保留；公开产物零来源表述；
  `lib/` 领域层纯净；数字只有一条来路；「没有数据」≠「0」；快照语义；估不出来就不给数字；
  新增检查自证会失败。
