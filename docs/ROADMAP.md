## 一、✅ P5.1 AI 推荐外卖 → **0.5.0（已上线）**

> 完整方案见 `docs/HANDOFF-AI-RECOMMEND.md`。**已按该方案实现**，落地情况与三处刻意的偏差见本节末尾。

- **目标**：饮食页/菜单库加「帮我挑外卖」——点一下 → 一次 DeepSeek 调用 → 返回 2~3 个候选 + 各一句理由。
- **红线（最高优先级）**：LLM 只做消歧与措辞，**绝不吐营养数字**；数字唯一来源 `nutritionOf` / `estimateDish`。
- **落地**：
  - `lib/ai/deepseek.ts` —— 浏览器直连的调用封装（超时、状态码翻译成能照做的话）。Key 由调用方传入，这一层不碰 localStorage，所以能在 Node 里被单测。
  - `lib/ai/recommend.ts` —— `pickableDishes`（候选池）/ `gapHints` / `buildPickMessages` / `sanitizeReason` / `parsePicks` / `pickDishesForGaps`。
  - `lib/ai/recommend.test.ts` —— 15 条用例，重点全在「让模型越权」：编菜单外的菜、理由里塞热量、多带一个 `kcal` 字段。
  - `app/components/today/WhatToEatCard.tsx` —— 「✨ 帮我挑」按钮 + `idle → loading → done | error` 状态机；失败/挑不出来**自动退回本地推荐**。
  - `scripts/browser-smoke.mjs` —— 新增 `checkAiPick`：无 Key 隐藏 / 有 Key 走通 / 模型编的菜不上屏 / 模型嘴里的数字不上屏（**四条都自证过会失败**）。
- **三处与计划的偏差**（都是刻意的，理由如下）：
  1. **入口放在首页的「今天还该吃点啥」卡上，不是饮食页/菜单库。**
     那张卡本来就是"下一口吃什么"的唯一出口，且已经握有今日缺口 + 菜单库 + 忌口三样数据；
     换到别的页面等于把同一件事拆成两处，用户要在两个页面之间找"到底哪个在推荐"。
  2. **用 `fetch` 而不是 `openai` SDK。** 依赖里那个 `openai` 是 9.6MB（1.29MB JS），
     而这里真正需要的只是"一次 POST，读一个 JSON 字段"。为一次调用背上一整个 SDK 不划算。
     （`openai` 目前仍是未使用的依赖，**没有删**——删依赖不在本次范围内，留待后续决定。）
  3. **模型回答用序号而不是菜名。** 序号必须落在候选范围内，白名单过滤就退化成一次下标越界检查，
     没有"名字长得像"的模糊空间；菜名那一路只作为"模型不听话"时的兜底（要求精确匹配）。
- **版本**：0.5.0（MINOR），三处已同步。
- **验收**：四道闸门全绿 + 冒烟四条新检查逐条自证会失败（见第 4 节第 23 条地雷）。

## 三、✅ P5.4 口语解析边界补强 → **0.5.1 / 0.5.2（已完成）**

> **2026-09-18：本项全部做完。** 四项里三项是"用户说清楚了、账本却静默算错或丢掉一份"，
> 而这些错**在界面上完全看不出来** —— 所以每一处都配了"不该切 / 不该粘"的反例测试。

### ✅ 0.5.1（用户实测上报）

- **「数字 + 量词」之间的空白**：在数字和量词之间打空格，
  「15 个饺子」会被切成 `["15", "个饺子"]`，界面上显示成**一条叫「5」的假食物 + 1 个饺子**（20g）。
  根因是 `glueMeasures` 的空白粘合只认**度量单位**（克 / g / ml）、不认**量词**（个 / 包 / 杯），
  于是那个空格被当成了「两样东西」的分隔。
- **中文数量词两位数**：`CN_UNIT_NUM` 原来是个**单字字符类**，匹配「十五」时只吃下「十」，
  剩下的「五」落进食物名 —— **15 个饺子被算成 10 份（2000g）**，比真实值大六倍多，且一声不吭。
  现在改成整词 `CN_NUM_WORD`，认「十 / 十五 / 二十 / 二十五 / 三十」。
  认不出来时返回 `null` 并退回「整串当食物名」，**绝不产出 NaN**（那会一路写进 `DietEntry.amount`）。

### ✅ 0.5.2（本项的剩余四项）

1. **「和 / 跟 / 加 / 以及 / 还有」切分** —— 与顿号统一处理：先换成顿号再按同一套规则切。
   用 `$1` 保住前一个汉字，于是**不需要 lookbehind** —— iOS Safari 16.4 之前不支持它，
   而这是正则**字面量**，引擎一 parse 就报错，整页白屏。
2. **约数连写**「两三」「三四」—— 取两个数里**小**的那个（宁低不高）并标 `approximate`；
   `quickadd.ts` 的 `withApprox` 据此标成估算，并在依据里写清取的是哪个值。
   含糊相加（「两三」→ 5）会**系统性高估**，比取保守值更糟。
3. **「一打」= 12 个** ——「打」加进 `PORTION_UNITS`，但**不进份量表**：
   它是固定的计数单位，不是跟食物相关的份量，所以在 `parseFragment` **出口**统一展开成「个」，
   之后走份量表里现成的 `个[鸡蛋]`。数字来路没变。
4. **数字后置**「饺子15个」 —— 新增 `TRAILING_COUNT_RE`；另外 `splitFragments` 加了
   `mergeBareAmounts`，把被空白切开的**纯份量段**并回前一段（「饺子 15个」→「饺子15个」），
   而「一包薯片 一杯奶茶」不受影响（第二段带着食物名）。

**单测 144 → 157 全绿。纯解析改动 → 单测就够**（不经过界面，冒烟抓不到）。

### ✅ 0.5.3（用户实测上报，仍是同一类：切段）

- **连写（不打标点）**：「一份饭两份肉一份包菜」整段进解析，食物名变成
  「饭两份肉一份包菜」→ 查库必然失败，界面上只说一句「库里没有」。
  现在 `splitFragments` 在按标点/空白/连接词切完之后，**每一段里再按「数量+量词」切**。
  ⚠️ 判据是"出现了**几个**份量"：两个以上才切，只有一个就切会把「三杯鸡」切坏。
- 同一类里更隐蔽的一种：「一碗米饭一个鸡蛋」原来**只记下米饭，鸡蛋那份直接消失**。
- 单测 157 → 159。

### ⚠️ 这一项**不解决**的（属 P6.1 食物库）

- **库里真没有这个食物**：`一份肉`、`一份包菜` 现在会各占一行、明说「库里没有」并给相近项。
  这是**对的** —— 硬配一条数值不对的更糟（见 `AGENTS.md` 地雷 16）。
  「包菜」这类常见菜要由 P6.1 按《中国食物成分表》补进来。
- **「15只饺子」→ 15 份 3000g**：`只` 在 `PORTION_UNITS` 里，但份量表没有 `只` + 饺子 的规则。
- **泛称**（「肉」「青菜」「主食」）不适合按单个条目收 —— 需要另想办法（追问用户一句？），
  目前走的是「库里没有 + 给相近项」。

- **红线**：守 `AGENTS.md` 地雷 15/19/20/25/26 —— 静默算错是重罪，估不准就标「估算」、给区间。
- **改动**：`lib/nutrition/parse.ts`（`glueMeasures` / `mergeBareAmounts` / `splitFragments` /
  `CN_NUM_WORD` / `TRAILING_COUNT_RE` / `PORTION_UNITS`）+ `quickadd.ts`（`withApprox`）+ 单测。

**依赖**：无。

### ✅ 第一批（0.6.0 已完成）：基础食材 + 引用台账

用户实测上报「一份包菜」记不上，查明根因是**库里 18 条素菜全是成品菜**（清炒时蔬、蒜蓉西兰花…），
一条生的基础蔬菜都没有。所以第一批先补**基础食材**，而不是原计划的"给存量条目补表号"。

- **新增 26 条**：卷心菜（别名 包菜/圆白菜/甘蓝）、西兰花、生菜、油麦菜、大白菜、小白菜、番茄、
  黄瓜、胡萝卜、白萝卜、冬瓜、苦瓜、丝瓜、南瓜、西葫芦、青椒、洋葱、韭菜、莲藕、山药、
  金针菇、鲜香菇、平菇、杏鲍菇、猪里脊、鸡胸肉。食物库 184 → **210** 条。
- **数值来源**：中国疾控中心营养与健康所「食物营养成分查询平台」（<https://nlc.chinanutri.cn>），
  逐条抓取、**kJ ÷ 4.184 换算成 kcal**、官方未检测的项目（这批全是膳食纤维）一律保持 `undefined`。
  该站声明数据**仅限非商业使用** —— 本项目是个人非商业项目，`meta.note` 与 README 都写明了。
- **`data/foodSources.json`（新增）**：数值**引用台账**。⚠️ 与本节原计划有一处**刻意偏差**：
  台账**只记引用标识**（foodId + 网页编号 + 取数日期），**不存标准值**。理由两条：
  ① 把表格数值整体复制进 MIT 仓库是版权问题；② `check-nutrition.mjs` 开头就写着
  「参照集不进仓库」的既有约定。要核对就按编号回官网查 —— 这才是"可复核"。
- **`scripts/check-food-reference.mjs`（新增，`npm run check:reference`）**：校验
  「写了外部来源的条目必须有台账」「台账与 source 不许单边存在」「page 是正整数」。
  ⚠️ **不做数值偏差比对**（没有标准值可比）—— 脚本会把这句边界打印出来，不让人误以为它证明了「数值全对」。
- **`check:nutrition` 新增份量表联动校验**：每条食物至少要有一条份量规则命中它。
  补这条检查时它一口气列出 **19 条**"有名字、有营养值、但没有份量规则"的食物，已全部补齐；
  顺带修了一个规则顺序错误（「一个蛋糕」以前会命中「鸡蛋」那条拿 55g）。
- **验收**：两道新检查都**逐条自证过会失败**（`check:nutrition` 一次破坏两处、分别断言两类问题都报；

## 十、红线与发布纪律（每次都要遵守）

- 版本号唯一来源 `package.json`，三处同步：`package.json` / `CHANGELOG.md` / `lib/changelog.ts`。
- 成块新功能 → MINOR；修 bug / 文案 / 样式 → PATCH；只改文档不升。
- 用户还看不到的成块工作，先记 `CHANGELOG.md` 的 `## [未发布]`，不动版本号。
- **1.0.0 起**：每次改动先开分支，用户确认后才 `--no-ff` merge 回 `main`。0.x 直接推 `main`。
- 红线摘要（完整见 `AGENTS.md` 第 3、4 节）：`recipe.*` 键名逐字保留；公开产物零来源表述；
  `lib/` 领域层纯净；数字只有一条来路；「没有数据」≠「0」；快照语义；估不出来就不给数字；
  新增检查自证会失败。
