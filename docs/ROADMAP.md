# 元气账本 · 路线图（1.0.0 之前）

> 这份文档是「接下来做什么」的**唯一权威来源**。版本号现状、已完成/进行中/规划中的事项、
> 大方向，都在这里。改动规划时更新本文件，而不是散落在聊天里。

**当前版本：0.3.0（已上线）** · 最后更新：2026-09-18

---

## 0. 大方向（一句话）

把「元气账本」从**能记账**打磨成**能用得顺、信得过**的个人健康账本，然后才谈「发正式版 1.0.0」。

三条主线，按优先级：

1. **补上用户明确要、还没做的能力**（AI 推荐外卖、更聪明的记录适配）
2. **把「数字可信」这件事做实**（食物库与份量表的准确度、可追溯性、更多校验）
3. **打磨体验与覆盖面**（条码扫描、睡眠/心情等已记录但没分析透的维度、导出/同步）

**1.0.0 的及格线**：上面三条主线里，第 1 条全部完成、第 2 条做到「关键数据有人工校核过」、
第 3 条至少落地一条（条码或睡眠分析），且用户实际用了一阵没再报「一上手就撞到」的问题。

## 3. 规划中（1.0.0 之前想做的，按建议顺序）

> 下面是**候选池**，不是承诺排期。每做一项，把它移到第 2 节并标注版本号。

### 3.1 记录体验再打磨（承接 0.3.0 的方向）

- **「一顿饭一键记」**：用户说「吃了顿饭」时，除了现在的「要具体点」提示，再给一个
  「一键记一顿」入口 —— 选常见搭配（盖饭 / 一菜一汤 / 两菜一汤），一次落多条记录。
  这是 0.3.0 里用户点名的痛点（「不能记录正餐」），当前只做了「餐次选择」这一半。
- **份量选择更顺**：现在改克数是手输数字，改成点「小包/一包/大包」这种档位更快。
  `portionOptions()` 已经能算出档位，只差 UI 接上。
- **口语解析的边界案例**：继续补「两三个」「半杯」「一打」这类数量词，以及更多量词。
  注意守 `AGENTS.md` 第 4 节第 15 条的坑（三种写法都要认、静默算错是重罪）。

### 3.2 把「数字可信」做实（食物库与校验）

- **食物库数值人工校核**：`check:nutrition` 只能证「算术自洽」，证不了「数值全对」。
  需要一套参照集（权威食物成分表）抽检库里 184 条的关键项（尤其钠、热量）。
  这是 1.0.0 及格线的一部分。
- **菜单库词表扩容**：现在常见菜识别率约四成（食物库没有成品菜条目）。两条路：
  - 用户侧「一键关联」已经做了一半（0.2.1），继续靠使用积累；
  - 库里补一批高频成品菜条目（如「黄焖鸡」「麻辣烫」），**但每条都要过数值校准**，不能拍脑袋填。
- **份量表与食物库的联动校验**：新增条目时，自动查它有没有对应的份量规则、规则里的 `match`
  是不是真能命中食物名/别名（现在靠 `check:nutrition` 手动看）。

### 3.3 覆盖面与体验（挑一条先落地）

- **条码扫描**：README 里已列在「规划中」。注意 `lib/nutrition/library.ts` 的注释提到
  「条码查询是唯一的例外」，意味着它需要联网查库 —— 涉及「纯前端 + 无后端」这个前提，
  要先想清楚数据源与许可，不能引入来源不明的数据。
- **睡眠 / 心情的深入分析**：这两个维度已经在「今天」页记录（`dailyCheckins`），
  但目前只有周报里的达标率，没有像饮食那样的分析。可以补「睡眠趋势」「心情与饮食/运动的关联」。
- **体重趋势更丰富**：`lib/weight.ts` 已有体重记录与图表，可补「目标体重进度」「周均体重」。
- **导出/同步体验**：备份已做（`lib/storage/backup.ts`），可补「导出提醒」（久未备份时提示）、
  「导入预览更友好」。

### 3.4 工程与质量

- **多语言 / 文案统一**：界面文案散在各组件里，可以抽一个文案表，方便后续改口径。
- **更多冒烟定向检查**：每新增一个「只能靠时间/交互看出来」的 bug 类型（如进度环动画），
  就补一条能自证失败的检查（参考 `AGENTS.md` 第 4 节第 22 条）。

## 5. 版本与发布纪律（每次都要遵守）

- 版本号唯一来源 `package.json`，三处同步：`package.json` / `CHANGELOG.md` / `lib/changelog.ts`。
- 成块新功能 → MINOR；修 bug / 文案 / 样式 → PATCH；只改文档不升。
- 用户还看不到的成块工作，先记 `CHANGELOG.md` 的 `## [未发布]`，不动版本号。
- **1.0.0 起**：每次改动先开分支（`feat/` `fix/` `docs/`），用户确认后才 `--no-ff` merge 回 `main`。
  0.x 阶段仍直接推 `main`。
- 发布后核对：5 页 200、`sw.js` 版本号（CDN 要等 1~3 分钟）、新旧文案正反两面 grep。

## 6. 关键红线（改任何东西前先读 `AGENTS.md` 第 3、4 节）

摘要（完整版以 `AGENTS.md` 为准）：

- `recipe.*` localStorage 键名与 JSON 结构**逐字保留**，只许加字段。
- 公开产物**零来源表述**，不新增「从零写起」这类反向断言。
- `lib/` 领域层纯净（相对导入、不 import UI/Next/localStorage）。
- **数字只有一条来路**：`nutritionOf(食物, 克数)`。
- 「没有数据」≠「0」；记录营养值是快照；估不出来就不给数字。
- 新增任何检查都要**自证会失败**。
