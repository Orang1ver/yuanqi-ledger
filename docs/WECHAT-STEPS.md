# 微信步数同步接入

此功能由独立微信小程序、云函数和账本中的可选入口组成。需要开发者配置并部署后才能使用；仓库里的默认配置不会连接任何真实服务。账本继续静态导出到 GitHub Pages，安卓 Capacitor 与 iPhone PWA 使用同一套读取接口，无需新增 iOS 原生工程。

## 用户操作

1. 在微信中进入已发布的小程序，阅读隐私指引，点击「授权并同步微信步数」。
2. 首次使用时，点击「生成连接码」再「复制连接码」。
3. 返回账本，在今日打卡区域展开「微信步数」，粘贴连接码，点击「连接并读取」。
4. 核对日期、步数和微信同步时间，点击「替换这一天的步数」。只更改所选日期的步数，喝水、睡眠和心情保持原值；已有奖励结算继续走原有流程。
5. 下次更新：先进入小程序同步，再回账本点击「读取最新步数」。不必重新生成连接码。

同一连接码可以粘贴到用户自己的多台设备，每台设备保留各自的本地账本。生成新码会立即撤销旧码，所有使用旧码的设备需重新连接。连接码有效期 90 天。

「移除本机连接」只删除当前设备的凭证；小程序的「撤销连接并删除云端步数」会撤销所有设备的读取权限并删除云端快照。账本中已经写入的记录保留。

## 开发者需要准备的配置

| 配置 | 位置 | 用途 |
| --- | --- | --- |
| 真实小程序 AppID | `wechat/project.config.json` 的 `appid` | 替换 `touristappid`，游客模式不能使用真实微信运动与云开发 |
| 云开发环境 ID | `wechat/miniprogram/config.js` 的 `envId` | 必须关联上述小程序 |
| 同一小程序 AppID | 云函数环境变量 `WERUN_APP_ID` | 校验调用身份和开放数据水印 |
| 允许的账本来源 | 云函数环境变量 `WERUN_ALLOWED_ORIGINS` | 逗号分隔的精确 origin，不含路径 |
| 云函数 HTTPS URL | 账本构建变量 `NEXT_PUBLIC_WERUN_API_URL` | 所有平台读取的固定接口地址 |
| 实际小程序名称 | 账本构建变量 `NEXT_PUBLIC_WERUN_MINIPROGRAM_NAME` | 用户搜索时看到的名称 |

AppID、环境 ID、服务 URL 都不是密钥。此方案不需要把 AppSecret 或 session_key 放进网页、小程序或仓库。

## 部署步骤

1. 在微信公众平台注册小程序，在微信开发者工具中导入 `wechat/`，填写真实 AppID 和环境 ID。确认账号可使用微信运动和云开发。
2. 在小程序后台填写用户隐私保护指引，声明微信运动步数的用途、云端存储、连接码授权读取和撤销入口。配置实际运营者与联系方式；页面调用 `wx.requirePrivacyAuthorize()`，拒绝时不继续同步。基础库使用支持该接口和云开发的当前稳定版本。
3. 在同一云环境创建 `werun_steps`、`werun_bindings` 两个集合。两个集合的客户端安全规则都使用 `wechat/database.rules.json`（禁止客户端直接读写）；云函数服务端 SDK 进行所有访问。
4. 云函数 `werun` 使用平台支持的 Node.js 运行时（建议 Node.js 18 或更新版本）。在开发者工具中右键目录「上传并部署：云端安装依赖」，入口为 `index.main`。安装依赖使用该目录内的 package-lock。设置 `WERUN_APP_ID`。
5. 将 `WERUN_ALLOWED_ORIGINS` 设置为实际入口。例如本项目：`https://orang1ver.github.io,https://localhost`。前者覆盖 iPhone Safari/PWA 和网页版，后者是当前安卓壳的 origin。开发时按需追加 `http://localhost:3000` 或实际本地预览地址，不能使用 `*`。
6. 在 CloudBase HTTP 网关将路径（例如 `/werun`）关联到 `werun` 云函数，使用集成响应，保留 `statusCode`、`headers` 和 `body`。配置 HTTPS 域名，允许 `GET` 与 `OPTIONS`，透传 `Authorization`。网关不要缓存此接口。若网关还配置了 CORS，必须与上述允许来源和请求头一致。接口使用自己的 Bearer 连接码鉴权，账本不发送云平台管理员密钥。
7. 在网关设置合理的调用限频和用量告警。HTTP 接口不提供创建用户或生成连接码的操作。上线前确保默认域名访问限制或中间提示页没有阻断 JSON API；必要时绑定正式域名。
8. 将根目录 `.env.example` 复制为 `.env.local`，填入 HTTPS 读取地址和实际小程序名称。网页执行 `BASE_PATH=/yuanqi-ledger npm run build`；安卓构建不带 `BASE_PATH`。这些变量在构建时注入，填写后必须重建网页/安卓资源。
9. 用体验版在真实安卓和 iPhone 微信中验证授权与步数，再提交小程序审核发布。未经审核时，仅已添加的体验者能用体验版；发布前不要引导普通用户搜索未上线的小程序。

HTTP 调用示例（`TOKEN` 为本机临时变量，不提交、不打印到日志）：

```sh
curl --fail --header "Authorization: Bearer $TOKEN" https://你的域名/werun
```

成功响应：

```json
{"days":[{"date":"2026-10-03","steps":1234}],"syncedAt":1790964000000}
```

## 数据与边界

- 微信数据只在用户主动进入小程序时更新，接口读取的是最近一次同步快照，不承诺持续后台或实时同步。
- 获取微信提供的最近 31 天数据。每日时间戳按北京时间转换成日期，与设备所在时区无关。无对应日期时不给零值、不写入账本；真实零步可以写入。
- 同步替换云端快照；账本每次只在用户点击后替换一天的步数，不累加、不批量覆盖历史。
- 云端只保存日期/步数、同步时间、派生用户标识、连接码哈希和到期时间。不会上传账本的饮食、体重、睡眠、AI Key 或其他记录。
- 云端步数快照保存到下一次同步覆盖或用户主动删除；31 天是一次获取/对外返回的窗口，不代表云数据库会自动删除旧快照。运营者需在隐私指引中如实说明，并按实际保留策略配置清理任务。
- 连接码使用 256 位随机秘密，只允许读取该用户的步数。凭证在请求头传输，不放 URL；数据库只保存秘密的哈希。不要在日志中记录请求头或云函数返回的连接码。
- `recipe.werunConnection.v1` 是绑定服务地址的本机凭证，不进入备份；导入到另一台设备后重新连接。它仍随「清空数据」被删除。已写入的步数随原有打卡记录正常备份。
- 未设置 `NEXT_PUBLIC_WERUN_API_URL` 时入口隐藏，默认构建不会请求微信服务。

## 验证

`npm run test:werun` 验证真实后端处理逻辑的鉴权、连接码轮换/撤销/到期、跨用户隔离、HTTP 不能写数据、CORS、北京时间归日，以及前端无效数据拒绝和备份凭证排除。云服务依赖在测试中替换为内存存储，不能代替微信真机联调。

还需执行项目原有 lint、静态构建、子路径检查、数据延续与浏览器冒烟。真机验收至少包括：拒绝授权后恢复、微信运动未启用、有效零步、跨日记录、读取旧快照、过期连接码、断网重试、重复写入不翻倍、已有喝水/睡眠记录不变、安卓壳 CORS 与 iPhone PWA 粘贴连接码。

官方参考：[微信运动 API](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/werun/wx.getWeRunData.html)、[云函数 HTTP 访问](https://docs.cloudbase.net/service/access-cloud-function)、[微信服务端 SDK](https://github.com/wechat-miniprogram/wx-server-sdk)。
